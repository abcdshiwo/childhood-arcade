# W165 Offline Importer

These tools create and verify a private, content-addressed W165 import batch.
They never serve a ROM, upload to a server, change Nginx, or publish a game.
Generated batches, extracted source data, ROMs, screenshots, evidence, and save
samples must remain outside the Git worktree.

## Requirements

- Node.js 24 or newer for `commit_batch.js` and `rollback_batch.js`.
- The byte-producing `prepare_batch.py` runtime is pinned to Python 3.12.13,
  Pillow 12.3.0, zlib 1.3.2 (compile and runtime), and libwebp 1.6.0. Python
  zlib determines normalized ZIP bytes; Pillow's libwebp determines thumbnail
  bytes. `prepare_batch.py` checks all four and fails closed on a mismatch.
  `verify_batch.py` only rehashes already generated bytes and does not need to
  encode ZIP or WebP output.
- A complete extracted W165 source root and the original encrypted cold-source
  archive. Do not execute files from the source tree.
- A database whose library migration state is `contracted`, a trusted active
  owner user ID, and a shared content-store root before committing a batch.

On this workstation, tests use:

```powershell
$env:ARCADE_IMPORT_PYTHON = 'C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe'
```

## Prepare And Verify

`prepare_batch.py` is dry-run by default. It reads the full source tree,
rebuilds the immutable candidate manifest, and prints the manifest JSON without
writing an output directory.

```powershell
& $env:ARCADE_IMPORT_PYTHON tools/arcade-import/prepare_batch.py `
  --source-root 'E:\Project\webemu\roms-inbox\W165_709-0b5f5c36\WinKawaks1.65 修正版' `
  --cold-source 'G:\下载\W165_709.7z' `
  --contracts-dir tools/arcade-import/contracts `
  --output-dir 'E:\Project\webemu\batch-output\w165-local'
```

Run the dry-run twice and compare the printed `manifest.manifestSha256`. A real
write requires `--apply`; it creates the output atomically. Repeating `--apply`
does not repair an existing batch: it rechecks the canonical manifest, report,
every expected normalized ZIP, and every content-addressed WebP. A missing,
modified, symlinked, or extra output file is rejected instead of returning a
successful no-op.

```powershell
& $env:ARCADE_IMPORT_PYTHON tools/arcade-import/prepare_batch.py --apply `
  --source-root 'E:\Project\webemu\roms-inbox\W165_709-0b5f5c36\WinKawaks1.65 修正版' `
  --cold-source 'G:\下载\W165_709.7z' `
  --contracts-dir tools/arcade-import/contracts `
  --output-dir 'E:\Project\webemu\batch-output\w165-local'

& $env:ARCADE_IMPORT_PYTHON tools/arcade-import/verify_batch.py `
  --manifest 'E:\Project\webemu\batch-output\w165-local\manifest.json' `
  --batch-root 'E:\Project\webemu\batch-output\w165-local' `
  --source-root 'E:\Project\webemu\roms-inbox\W165_709-0b5f5c36\WinKawaks1.65 修正版' `
  --cold-source 'G:\下载\W165_709.7z' `
  --contracts-dir tools/arcade-import/contracts
```

The verifier rehashes the cold source, source inventory, WebP assets,
normalized ZIPs, and every recorded `source.zip!member`. It also checks the
frozen 656/655/654 candidate identities and source/thumbnail totals for a
production-size batch.

## Batch Contents

The generated directory contains only:

- `archives/`: deterministic normalized ROM ZIPs for candidates that are not
  statically blocked or unsupported.
- `thumbnails/sha256/`: content-addressed WebP files.
- `manifest.json` and deterministic `report.md`.

All 656 candidates remain in the manifest. A static source match is
`unverified`, not public-ready. The commit tool records blocked and unsupported
candidates in the operation ledger but does not create runtime builds for them.

The 9 raw EEPROM samples and 26 Kawaks RLE SRAM samples are retained in source
evidence. Their decoded SHA-256, candidate filename, and mapping state are
recorded in `saveSampleEvidence`; no `.nv` or `.fs` file is generated or
injected. `kof99nd.srm` is deliberately left unmapped. Runtime seeding needs a
separate, validated feature and is outside this importer.

## Commit

Commit is also dry-run by default. It checks the manifest against the
hash-pinned contract files, previews content-store publications, and writes
nothing without `--apply`.

```powershell
node tools/arcade-import/commit_batch.js `
  --db 'E:\Project\webemu\local-data\app.db' `
  --asset-root 'E:\Project\webemu\local-data\assets' `
  --manifest 'E:\Project\webemu\batch-output\w165-local\manifest.json' `
  --batch-root 'E:\Project\webemu\batch-output\w165-local' `
  --contracts-dir tools/arcade-import/contracts `
  --owner-user-id 1
```

Add `--apply` only after a successful `verify_batch.py` result and a database
backup. The command creates private builds; it does not select a public active
build or claim runtime validation.

`--contracts-dir` is the trust anchor: its `SHA256SUMS.txt` must cover exactly
the frozen JSON ledgers. Pass `--repo-root <release-root>` only when a
hash-pinned core artifact is absent from the database; the tool will then
rehash the exact JS/WASM files named by the contract before registering them.

`<db>.arcade-import.lock` serializes commit and rollback. Treat an existing
lock as active or stale until it has been inspected; do not delete it blindly.

## Rollback

Rollback is dry-run by default and only reverses operations recorded for this
batch. It refuses stale rows, retains assets/builds referenced by later rooms,
saves, or batches, and records a `rollback_failed` state if preflight detects a
conflict. Once the conflicting state is intentionally restored, running the
same command again can resume the rollback.

```powershell
node tools/arcade-import/rollback_batch.js `
  --db 'E:\Project\webemu\local-data\app.db' `
  --asset-root 'E:\Project\webemu\local-data\assets' `
  --manifest 'E:\Project\webemu\batch-output\w165-local\manifest.json' `
  --batch-id 'w165-<cold-source-sha-prefix>'
```

Add `--apply` only after reviewing the dry-run evidence. Do not restore a
whole database after user writes have resumed; use the operation ledger or a
forward fix so rooms and save states created after import are preserved.

## Transfer And Deployment

This repository does not automatically transfer the batch. Keep the cold
source, prepared batch, manifest, report, and verifier result together. A
future deployment should copy verified fixed-size chunks to an isolated staging
directory, rehash them before assembly, rehearse against a database copy, and
then run the same verify/commit commands locally on the target. Do not put an
archive password, SSH private key, session cookie, or ROM bytes into reports,
Git, or command logs.
